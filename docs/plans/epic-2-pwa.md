# Epic 2 — Installable, offline app (PWA)

Plan written by Claude and reviewed by codex. Implemented story by story by agy (Gemini). One branch and one PR per story.

## Context

- React 19 + Vite 8 + TypeScript. Deployed by `cf` (1.0.0-beta.26) as an assets-only Worker; `@cloudflare/vite-plugin`
  2.0 beta **forces** the client build into `.cloudflare/output/v0/workers/default/assets` (top-level `build.outDir` is ignored).
- `npm run preview` runs **without** the Cloudflare plugin (`vite.config.ts`, `isPreview` branch), serving that same folder.
- Headers: `public/_headers`. The CSP applies to every path, including `/sw.js`. A service worker's own `fetch()` calls are governed by the CSP of its `sw.js` response.
- Photos: `public/assets/img/*.jpg`, **46 files, 28 MB**, listed in `src/data/photos.js` (generated by `tools/fetch_photos.py`).
- Vercel (old site, `feature/starting`) is out of scope. Never touch `vercel.json`.

## Decisions

1. **Precache only the app shell** (HTML/JS/CSS/icons/manifest). Photos are **runtime-cached** (CacheFirst), and users can explicitly
   **"Save photos for offline"** (28 MB, opt-in). Recompressing the photos is a separate perf story (E5).
2. Photo URLs become **root-relative** (`/assets/img/…`). Relative URLs break on nested paths and wouldn't match the cache rule.
3. `registerType: "prompt"`: never reload under the user. An update toast in E2-S3.
4. CSP `connect-src` for Google Fonts: **confirmed needed** (E2-S2). On Cloudflare the service worker's font fetches were blocked by `default-src 'self'`, which broke fonts online too. `connect-src 'self' https://fonts.googleapis.com https://fonts.gstatic.com` was added to `public/_headers`.
5. Service worker disabled in `vite dev` (`devOptions.enabled: false`).

## E2-S2 Offline guide — `feat/E2-S2-offline`

**Story:** As a traveller with no signal, I want the guide to work offline.

agy (files):

- `src/data/photos.js` + `tools/fetch_photos.py`: `"src": "assets/img/…"` → `"src": "/assets/img/…"` (46 entries).
- `pwa.config.ts`: `runtimeCaching` → photos (same-origin `/assets/img/`, CacheFirst `photos`, statuses [0,200], maxEntries 60),
  Google Fonts CSS (StaleWhileRevalidate `google-fonts-css`), font files (CacheFirst `google-fonts`, 1 year, maxEntries 30).
- `src/pwa/savePhotos.ts`: `savePhotosForOffline(urls, onProgress)` → concurrency 4, absolute URLs (`new URL(src, location.origin)`),
  skips already-cached ones, `cache.put` into `photos`, returns `{ saved, failed }`. Also `countSavedPhotos(urls)`.
- `src/pwa/SaveOffline.tsx` in the footer: states unsupported / idle / saving `n / 46` / done / partial (with "Try again").
  Calls `navigator.storage.persist()` first. Shows "about 28 MB". `aria-live="polite"`.
- CSS for the panel in `css/styles.css` using the existing tokens (light and dark).

Claude: CSP check in a real browser. If the SW's font fetches are blocked, add `connect-src 'self' https://fonts.googleapis.com https://fonts.gstatic.com`.

Acceptance:

- [ ] Online → save → **server stopped and network emulated offline** → reload `/` and `/some/deep/path`: every section renders, **every `<img>` loads** (scroll through to trigger lazy loading), fonts come from the `google-fonts` cache, 0 errors
- [ ] Photos seen online are available offline without pressing save
- [ ] Partial failure is reported ("44 of 46 saved — 2 failed. Try again") and never shown as complete; already-saved photos are detected on reload
- [ ] No SW / no Cache API → the panel explains and doesn't offer a broken button

## E2-S3 Update prompt — `feat/E2-S3-update-toast`

**Story:** As a user, I want to know when a new version is out.

agy (files): `src/pwa/UpdateToast.tsx` with `useRegisterSW` (`virtual:pwa-register/react`; types `vite-plugin-pwa/react`), which replaces `registerSW.ts`:

- `needRefresh` → "A new version is available." [Reload] (`updateServiceWorker(true)`) [Later]
- `offlineReady` → "Ready to work offline." once, auto-hide 4 s
- `registration.update()` hourly and when the tab becomes visible (only if a registration exists; no duplicate timers)
- `role="status"`, `aria-live="polite"`, focusable buttons, dark mode, `prefers-reduced-motion` respected; styles in `css/styles.css`

Acceptance:

- [ ] First install: only "Ready to work offline", no update toast; a normal reload with no new version shows nothing
- [ ] Build A open → deploy build B → toast appears → Reload → B's content; "Later" hides it until the next check
- [ ] Two tabs: reloading one activates the update; the other doesn't break (shows the toast or reloads cleanly)
